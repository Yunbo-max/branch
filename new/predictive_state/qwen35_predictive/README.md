# Native Qwen3.5-4B: GDN/GQA-Grounded MTP and Future-State Pilot

**Active new main line (2026-11-15).** We reuse the **pretrained** Qwen3.5-4B (24 GDN + 8 GQA, one pretrained MTP block). The earlier `psdraft/` independent randomly initialized GDN remains only as an archival baseline. All 4B backbone/native-MTP weights are **frozen**.

## What is implemented, and what is not

| Case | Pretrained features used by native MTP | Trainable component | Current research test |
|---|---|---|---|
| `c00_native` | Released MTP alone | None | Recursive pretrained-MTP reference |
| `c01_gdn` | Actual GDN mixer readout from layer 26 | One zero-initialized residual adapter | Does GDN's readout help? |
| `c02_gqa` | Actual GQA mixer readout from layer 27 | The **same sized** adapter | Does history retrieval help? |
| `c03_fusion` | Normalized GDN+GQA readouts | The **same sized** adapter | Are the streams complementary? |
| `c04_state` | C03 streams + real GDN recurrent matrix | C03 adapter + training-only state-jump head | Can MTP predict a projection of future GDN state? |

Qwen has per-layer/per-head GDN matrices, not one universal global state. The true native GDN cache is `[B,32,128,128]` at selected layer 26. C04 uses four heads with a *fixed random bilinear sketch* `P^T S Q`; it is **not** a hidden-state proxy or a full state reconstruction. C04 predicts the **change** in that sketch after its own K draft tokens; the target state is generated by the frozen backbone on that same draft, after sampling. This is auxiliary state supervision, not yet a production block jump.

C00 first proposal comes from the frozen main head, followed by recursive reuse of the **released MTP layer**. This specific K-step policy differs from AKR's alternating NTP+MTP full language generation, which remains a separate strong baseline. No Qwen native MTP tensors are silently discarded.

**Training**: independently sample `K` future tokens from the current adapted MTP, then query the frozen backbone over **exact same sampled token IDs**; minimize full-vocabulary forward KL on every valid proposal position. C04 also trains state-sketch prediction by normalized MSE. Only the small modules backpropagate. Gold answers are never used in the training/rollout; teacher sees only an ordinary question prompt and the student's sampled prefix.

**MTP prefill requirement:** the released native MTP layer first consumes the **entire accepted-prefix hidden sequence** paired with shifted token embeddings (as in AKR), not only the last boundary hidden. Later draft steps reuse the MTP's own KV cache. Rebuilding that full MTP prefill on every independent reference block is costly at long context; it is not a fast production decode implementation.

**Evaluation**: one-block reference speculative verification using the exact p/q acceptance and residual correction. Reports paired acceptance length, fraction all accepted, KL, TV and (for C04) state-sketch loss; saves each raw row. Teacher currently **recomputes entire prefix**, so the recorded reference time **does not** measure cached speculative generation throughput, and no acceleration is claimed.

The novelty claim **is not** GDN+GQA+MTP or on-policy KL. It will require showing that an efficiently predicted *next state* can support multi-token/block decoding with reduced serial work, without hurting consistency. C04 tests only whether such state prediction is learnable.

## Where to start

Read [RUNBOOK_ZH.md](RUNBOOK_ZH.md) for the complete commands; run `python -m qwen35_predictive.cli plan` in `new/predictive_state`. The native model/weights/checkpoint manifest and native MTP implementation are taken from [AKR research/mtp-opsd-baseline](https://github.com/Yunbo-max/AKR/tree/research/mtp-opsd-baseline), which must be checked out separately. No extra model weights or datasets are uploaded to GitHub.

CPU mock tests: `python -m pytest -q tests/test_qwen35_predictive.py`. These tests do **not** prove CUDA, 4B loading, native MTP cache correctness or speed; `qualify` on the actual BF16 CUDA GPU remains mandatory before any research result.
